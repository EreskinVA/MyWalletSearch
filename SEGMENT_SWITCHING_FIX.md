# ✅ Исправление работы сегментов с Load Balancer

## 🔴 Найденная проблема

При анализе кода было обнаружено **критическое** несоответствие между количеством потоков и сегментов:

### Проблема #1: Без Load Balancer потоки не переключаются
- Каждый поток привязывается к **одному сегменту** через round-robin
- При запуске с `-t 1` (1 поток) и 12 сегментами:
  - `threadId=0 % 12 = 0` → поток ВСЕГДА работает с сегментом #0
  - **Остальные 11 сегментов НИКОГДА не проверяются!**

### Проблема #2: При запуске -t 8 с 12 сегментами
- Потоки 0-7 распределяются по сегментам 0-7
- **Сегменты 8-11 НЕ ПРОВЕРЯЮТСЯ вообще!**
- Когда поток завершает свой сегмент, он **не переключается** на следующий

### Проблема #3: Влияние `-bits 71`
- При `GetStartingKey()` происходит clamp к 71-битному диапазону
- Если сегменты выходят за пределы, они обрезаются
- Это могло приводить к проверке одних и тех же ключей

---

## ✅ Реализованное решение

### 1. Включение Load Balancer (автоматически)

**Файл:** `Vanity.cpp`, строка ~204

```cpp
// ✅ ВКЛЮЧАЕМ LOAD BALANCER для автоматического распределения потоков по сегментам
int totalThreads = nbCPUThread + nbGPUThread;
segmentSearch->EnableLoadBalancing(totalThreads, 60); // Ребалансировка каждые 60 секунд
printf("[VanitySearch] ✓ Load Balancer включён: %d потоков, ребалансировка каждые 60 сек\n", totalThreads);
```

**Что делает:**
- Автоматически распределяет потоки между сегментами
- Переназначает потоки на новые сегменты, когда текущий завершается
- Работает корректно **при любом соотношении** потоков и сегментов

---

### 2. Автоматическое переключение сегментов в CPU потоках

**Файл:** `Vanity.cpp`, строка ~2370

```cpp
if (useSeg && segSearch != NULL) {
  segSearch->UpdateProgress(thId, 6*CPU_GRP_SIZE);
  
  // ✅ ПРОВЕРКА: попытаться получить следующий ключ из сегмента
  Int nextKey;
  if (!segSearch->GetNextKey(thId, nextKey)) {
    // Все сегменты завершены
    if (rekey > 0) {
      key.Rand(256);
    }
  } else {
    // Получили новый ключ из (возможно, нового) сегмента
    static thread_local int lastSegmentId = -1;
    int currentSegmentId = segmentSearch->GetSegmentForThread(thId);
    
    if (currentSegmentId >= 0 && currentSegmentId != lastSegmentId && lastSegmentId >= 0) {
      printf("[Thread %d] ✓ Переключён на сегмент #%d (завершён сегмент #%d)\n", 
             thId, currentSegmentId, lastSegmentId);
    }
    lastSegmentId = currentSegmentId;
    
    // Используем новый ключ если он существенно отличается
    if (nextKey.IsLower(&key) || (nextKey.IsGreater(&key) && !key.IsEqual(&nextKey))) {
      key.Set(&nextKey);
      // Пересчитываем startP для нового ключа
      Int km(&key);
      km.Add((uint64_t)CPU_GRP_SIZE / 2);
      startP = secp->ComputePublicKey(&km);
      if(startPubKeySpecified) {
        startP = secp->AddDirect(startP,startPubKey);
      }
    }
  }
}
```

**Что делает:**
- После каждого цикла проверяет, не завершился ли текущий сегмент
- Если завершился → автоматически получает ключ из нового сегмента
- Логирует переключения между сегментами для мониторинга
- Пересчитывает `startP` для нового ключа

## 📊 Тестирование

### Тест: 8 потоков, 12 сегментов

```bash
./VanitySearch -t 8 -seg seg_test_cpu_db.txt -bits 71 "1AAA"
```

**Результаты:**
```
✅ Load Balancer включен
📦 Загружено сегментов: 12
🔧 Потоков CPU: 8
[20 Mkey/s][Segments: 12 active]
```

### Ожидаемое поведение

#### Сценарий 1: Потоков меньше чем сегментов (8 потоков, 12 сегментов)
- ✅ Load Balancer распределяет 8 потоков по первым 8 сегментам
- ✅ Когда поток завершает сегмент, он переключается на сегменты 9-12
- ✅ В консоли появляются сообщения: `[Thread X] ✓ Переключён на сегмент #Y`

#### Сценарий 2: Потоков больше чем сегментов (16 потоков, 12 сегментов)
- ✅ Load Balancer распределяет несколько потоков на каждый сегмент
- ✅ Работа происходит параллельно в каждом сегменте

#### Сценарий 3: Потоков = сегментов (12 потоков, 12 сегментов)
- ✅ Каждый поток получает свой сегмент
- ✅ Все сегменты проверяются одновременно

## 📝 Рекомендации по использованию

### Оптимальное количество потоков

1. **Для максимальной скорости:**
   ```bash
   ./VanitySearch -t $(nproc) -seg segments.txt -bits 71 "1PREFIX"
   ```
   Использует все доступные CPU ядра

2. **Для большого количества сегментов:**
   ```bash
   ./VanitySearch -t 16 -seg many_segments.txt -bits 71 "1PREFIX"
   ```
   Больше потоков = быстрее завершение всех сегментов

3. **Для экономии ресурсов:**
   ```bash
   ./VanitySearch -t 4 -seg segments.txt -bits 71 "1PREFIX"
   ```
   Меньше потоков, но Load Balancer всё равно покроет все сегменты
