# 🎯 Стратегии генерации сегментов для VanitySearch

## Обзор

Умный генератор сегментов `smart_segment_generator.py` предоставляет 5 различных стратегий для оптимального покрытия заданного диапазона поиска. Каждая стратегия имеет свои преимущества и оптимальные сценарии использования.

---

## 📊 Таблица сравнения стратегий

| Стратегия | Распределение | Приоритеты | Направления | Лучше для |
|-----------|---------------|------------|-------------|-----------|
| **smart_mixed** | Центр + края + случайные | 9, 7, 5 | Смешанные | Универсальный поиск |
| **golden_ratio** | По φ (0.618) | 9-7 (от центра) | Чередующиеся | Элегантное покрытие |
| **center_heavy** | 60% центр, 40% края | 9 (центр), 6 (края) | 50/50 | Ключ вероятно в центре |
| **edges_focus** | 70% края, 30% центр | 8 (края), 4 (центр) | 50/50 | Ключ вероятно на краях |
| **random_scatter** | Равномерное случайное | 5-9 (случайно) | Случайные | Исследование |

## 1. 🎯 smart_mixed — Универсальная смешанная стратегия

### Описание
Комбинирует три подхода: центральные сегменты с высоким приоритетом, зеркалированные края со средним приоритетом и случайные точки с низким приоритетом.

### Алгоритм
```
Для каждого сегмента (циклически):
  seg_idx % 4 == 0: Центральный сегмент (up/down чередуется)
  seg_idx % 4 == 1: Левый край (up)
  seg_idx % 4 == 2: Правый край (down, зеркально)
  seg_idx % 4 == 3: Случайная точка (случайное направление)
```

### Приоритеты
- **9**: Центральные сегменты (высший приоритет)
- **7**: Края (средний приоритет)
- **5**: Случайные точки (низкий приоритет)

### Распределение направлений
- **UP**: ~75% (центр, левый край, случайные)
- **DOWN**: ~25% (правый край)

### Когда использовать
- ✅ **Универсальный случай**: Нет конкретной гипотезы о местоположении ключа
- ✅ **Первичный поиск**: Начальное исследование диапазона
- ✅ **Сбалансированное покрытие**: Равномерное распределение ресурсов

### Пример вывода
```
key 0x6B9C54A6921736D556 0x6BAF72015D867D2AAB up grp1_center_1 9
key 0x6B3333333333340000 0x6B46508DFEA27A5555 up grp1_left_2 7
key 0x6C057619F0FB39AAAB 0x6C189374BC6A800000 down grp1_right_3 7
key 0x6BE01A0ECCF46F4094 0x6BF337699863B595E9 up grp1_rand_4 5
```

## 2. ✨ golden_ratio — Золотое сечение

### Описание
Распределяет сегменты по золотому сечению (φ ≈ 0.618), математически элегантный подход для равномерного покрытия.

### Алгоритм
```
Для каждого сегмента:
  ratio = (seg_idx + 1) / total_segments
  phi_ratio = (ratio * φ) % 1.0
  center = range_start + (range_size * phi_ratio)
```

### Приоритеты
- Распределяются динамически в зависимости от расстояния от центра:
  - **9-8**: Ближе к центру (0.5)
  - **7-1**: Дальше от центра

### Распределение направлений
- **UP**: 50% (чётные индексы)
- **DOWN**: 50% (нечётные индексы)

### Когда использовать
- ✅ **Математически элегантное покрытие**: Оптимальное распределение Фибоначчи
- ✅ **Равномерное исследование**: Без предположений о местоположении
- ✅ **Эстетика + эффективность**: Красивое и эффективное распределение

### Математика
Золотое сечение обеспечивает минимум "кластеризации" точек:
- φ = (1 + √5) / 2 ≈ 1.618
- 1/φ ≈ 0.618

### Пример вывода
```
key 0x6B4D154D19D9650956 0x6B6032A7E548AB5EAB up grp1_phi_1 7
key 0x6B7086146637393D56 0x6B83A36F31A67F92AB down grp1_phi_2 8
key 0x6B93F6DBB2950D6D56 0x6BA714367E0453C2AB up grp1_phi_3 9
key 0x6BB767A2FEF2E1A556 0x6BCA84FDCA6227FAAB down grp1_phi_4 9
```

## 3. 🔵 center_heavy — Акцент на центре

### Описание
Концентрирует 60% вычислительных ресурсов в центральной трети диапазона, 40% на краях.

### Алгоритм
```
central_segments = 60% от total
edge_segments = 40% от total

Центральные: Плотно упакованы в центральной трети
Краевые: Разрежены на левом и правом краях
```

### Приоритеты
- **9**: Все центральные сегменты (высший приоритет)
- **6**: Краевые сегменты

### Распределение направлений
- **UP**: 50% (чередуется)
- **DOWN**: 50% (чередуется)

### Когда использовать
- ✅ **Гипотеза о центре**: Есть основания полагать, что ключ в центре диапазона
- ✅ **Анализ паттернов**: Предыдущий анализ показал концентрацию в центре
- ✅ **Оптимизация по времени**: Быстрее проверить наиболее вероятную зону

### Пример вывода
```
# 6 центральных сегментов (приоритет 9)
key 0x6B7949801D208B38E6 0x6B8607BCA4C00F71C9 up grp1_core_1 9
key 0x6B8607BCA4C00F71C9 0x6B92C5F92C5F93AAAC down grp1_core_2 9
...
# 4 краевых сегмента (приоритет 6)
key 0x6B3333333333340000 0x6B4FDF3B645A1D8000 up grp1_edge_left_1 6
key 0x6BFBE76C8B43968000 0x6C189374BC6A800000 down grp1_edge_right_2 6
```

## 4. 🔷 edges_focus — Акцент на краях

### Описание
Противоположность center_heavy: 70% ресурсов на краях, 30% в центре.

### Алгоритм
```
edge_segments = 70% от total (половина слева, половина справа)
center_segments = 30% от total (разреженные)

Левый край: Плотно упакованы
Правый край: Плотно упакованы (зеркально)
Центр: Разреженные проверки
```

### Приоритеты
- **8**: Краевые сегменты (высокий приоритет)
- **4**: Центральные сегменты (низкий приоритет)

### Распределение направлений
- **UP**: 50% (левый край)
- **DOWN**: 50% (правый край)

### Когда использовать
- ✅ **Гипотеза о краях**: Ключ вероятно на границах диапазона
- ✅ **Дополнительный поиск**: После неудачного center_heavy
- ✅ **Специфические паттерны**: Анализ показал активность на краях

### Пример использования
Puzzle 71, если анализ показал, что предыдущие ключи были найдены ближе к границам 2^70 и 2^71.

## 5. 🎲 random_scatter — Случайное распределение

### Описание
Генерирует сегменты в случайных местах без перекрытий. Используется для исследования и устранения "слепых зон".

### Алгоритм
```
Для каждого сегмента:
  1. Выбрать случайный центр
  2. Проверить перекрытия с существующими
  3. Если нет перекрытий - добавить
  4. Случайные направление и приоритет
```

### Приоритеты
- **5-9**: Случайно назначаются

### Распределение направлений
- **UP**: ~50% (случайно)
- **DOWN**: ~50% (случайно)

### Когда использовать
- ✅ **Исследование**: Проверка гипотезы о случайном распределении
- ✅ **Устранение bias**: Избежать систематических ошибок других стратегий
- ✅ **Параллельный поиск**: В сочетании с другими стратегиями
- ✅ **Тестирование**: Проверка различных зон

### Особенность
Может не создать все запрошенные сегменты, если не хватает места (выводит предупреждение).

## 📈 Оптимизация параметров

### Количество сегментов в группе
- **4-6**: Малое количество CPU потоков (≤4)
- **6-12**: Оптимально для большинства случаев (8-16 потоков)
- **12-24**: Много CPU потоков (≥32) или GPU

### Количество групп
- **1**: Простой поиск, один диапазон
- **2-5**: Оптимально для разделения работы
- **5+**: Параллельные стратегии или очень большие диапазоны

### Минимальный размер сегмента
- **100,000**: Очень маленькие сегменты (быстрое переключение)
- **1,000,000**: Оптимально (default)
- **10,000,000**: Большие сегменты (меньше overhead на переключение)

## 🔬 Математические основы

### Покрытие диапазона
Для диапазона `[start, end]` с `N` сегментами размера `S`:

```
Coverage = (N × S) / (end - start) × 100%
```

Рекомендуется: Coverage ≈ 1-5% для первичного поиска

### Плотность сегментов
```
Density = N / (end - start)
```

Высокая плотность = больше перекрытий, лучше покрытие
Низкая плотность = быстрее, но могут быть пропуски

### Load Balancer
Автоматически распределяет сегменты по потокам:
- **8 потоков, 12 сегментов**: 8 потоков работают, 4 сегмента в очереди
- **8 потоков, 6 сегментов**: 6 потоков работают, 2 простаивают (не оптимально)

**Рекомендация**: `segments_per_group ≥ cpu_threads + 2`
